The avatar's semantic motion API

How a spoken command becomes movement with the new planner, and a playground with every dial of the rig.

1. What changed, in one minute

Today's planner (a language model) answers a command by writing raw dial keyframes: "at 0.3 s set the right paw to x −0.7, y 0.9, z 0.9…". It has to guess the numbers that put a paw on the chin, and it often guesses wrong.

The semantic API lets the model write a short program in motion words instead: reach('right', 'chin'), look_at('upper_left'), raise_brow('left'). Ordinary code then works out where the chin is, bends the arm so the hand lands there, times and smooths every move, and only then turns the result into the same dials the renderer has always read.

Why this helps

The model is good at words (“chin”, “upper left”, “three taps”) and bad at guessing a dozen coupled numbers. Units are real — centimetres, degrees, seconds, 0..1 amounts — and targets are named body parts, so “touch your nose” cannot miss the nose by a hand's width. Sides are the avatar's own left/right; the code handles the mirror.


Each finished statement starts moving while the model is still writing the next, so the planner is told to open with the main move (often one with parallel(): block: move + look + expression together), use the hand on the target's side, and keep it to 2–6 statements. Blinking, breathing, idle motion and lip sync are left to the live avatar.









2. The pipeline in one picture



How it layers with everything else


    

  • A commanded move owns only the dials it drives. A head scratch drives arm and head dials; blinking, breathing, lip sync and gaze following keep running on everything else.
    • 

  • It eases in from wherever each dial is (about 0.2 s) and eases back when its part is done.
    • 

  • Mouth dials yield to speech: while the avatar talks, lip sync keeps the mouth.
    • 

  • Gaze belongs to the move only while the program aims the eyes; then the eyes go back to following you.
    • 

  • A newer command, or “stop”, interrupts the running one.

3. Does it work better?


Bake-off: 106 sealed commands × 3 tries each, scored by automatic checks and a blind judge.


semantic API   today's raw keyframes






Honest read: it does what was asked far more often, especially anything aimed at a place (“touch your left shoulder”) or with several steps. It is not more lifelike yet: a blind judge took it for real motion-capture 27% of the time (today's planner 20%, real capture 83%). Moves still read as robotic: even timing, no weight shift, hands travel in tidy arcs.


Where it is worse, and the fine print

Whole-body moves (jump, spin, crouch): 87% vs 98%. Unusual body moves: 71% vs 76%. Naturalness head-to-head: wins 59% of blind pairwise comparisons vs 56%. These are offline numbers from the bake-off; the live demo's numbers (time to first motion, did it do it) are filled in separately.
